# 알약 카운터 0.7.0

휴대폰에서 사진을 촬영하거나 선택해 알약을 세고, 번호를 확인·수정한 후 저장하는 웹앱입니다.

## 의약품예제소분과 PC 라벨 출력

1. 프린터가 연결된 PC에서 웹앱 → **의약품예제소분 → PC·프린터 연결 → 이 PC에서 라벨 받기**를 엽니다.
2. 휴대폰의 기본 카메라로 PC의 QR을 읽고 링크를 엽니다. 두 기기는 인터넷에 연결되어 있어야 합니다. 같은 공유기인지와 관계없이 비공개 중계 서버로 연결됩니다.
3. 제품 바코드를 촬영하거나 입력한 뒤 적용합니다. 심평원 공개 표준코드 데이터에서 제품명·함량/규격·제조/수입사를 자동 조회합니다. 결과를 현재 포장과 대조한 후 진행합니다. 목록에 없거나 조회가 실패하면 직접 입력할 수 있고, 저장한 정보는 해당 브라우저에서 불러옵니다. 제조번호·사용기한은 이전 제품에서 재사용하지 않습니다.
4. **수량 카운팅 시작**에서 촬영하거나 사진을 선택하고, 번호를 수정·대조한 뒤 **확인 완료**를 누릅니다. 확인한 수량이 소분 라벨에 반영됩니다.
5. 소분일·필요한 경우 소분 후 사용기한·용지 크기·매수를 설정하고 최종 확인 후 **PC로 라벨 전송**을 누릅니다.
6. PC의 출력 대기 목록에서 **라벨 보기·출력 → 프린터 선택·인쇄**를 누릅니다. 프린터 드라이버에서 용지 크기, 배율 100%, 여백 없음, 머리글·바닥글 끄기를 설정합니다.
7. 실제 출력물을 확인한 다음 **실제 출력 완료 확인**을 눌러 휴대폰에 완료 상태를 전달합니다. 인쇄 창 취소를 출력 성공으로 처리하지 않습니다.

PC에 설치한 USB 라벨프린터나 공유 프린터를 사용할 수 있습니다. 브라우저는 공유기의 프린터 목록을 직접 검색하거나 무인 자동 인쇄하지 않습니다. **테스트 라벨로 프린터 선택**에서 운영체제의 프린터 선택 창을 엽니다. 유팜데일리 연동은 해당 PC의 코드·출력 인터페이스가 확보된 뒤 별도로 연결해야 합니다.

지원 용지: 60×40, 70×50, 50×30 mm. 긴 제품명 등의 내용이 용지 영역을 넘으면 전송/인쇄를 막고 더 큰 라벨을 선택하도록 안내합니다. 날짜를 임의로 추정하지 않으며 GS1 (01)/(10)/(17)을 읽은 경우에도 포장과 대조해야 합니다. 일반 EAN/UPC/Code128, GS1 DataMatrix는 ZXing 0.1.5와 지원 브라우저의 BarcodeDetector로 읽습니다.

### 라벨 중계 서버

`api/print-relay.js`가 Vercel의 **비공개 Blob 저장소**를 사용합니다. 연결된 프로젝트에 `BLOB_READ_WRITE_TOKEN` 또는 지원되는 OIDC의 `BLOB_STORE_ID` 설정이 필요합니다. 토큰을 소스·브라우저·로그에 넣지 않습니다. PC 소유 토큰과 휴대폰 전송 토큰은 별도이며, QR에는 전송 권한만 담습니다. 라벨 조회·출력 완료·연결 종료는 PC 권한이 필요합니다.

연결은 8시간 후 만료됩니다. 출력/취소 확인 시 라벨 본문을 삭제하고 최소 상태만 남깁니다. PC에서 연결 종료 시 해당 연결의 데이터를 지웁니다. 만료된 잔여 파일은 다음 PC 연결 생성 시 제한된 묶음으로 정리됩니다(만료 시각에 즉시 물리 삭제하는 스케줄러는 아닙니다). 새 연결 생성 시 요청당 최대 200개의 오래된 파일을 정리합니다. 최대 20개의 라벨이 대기하며, 재시도는 같은 요청 ID를 사용해 중복을 방지합니다. 제품·수량·날짜 등의 라벨 내용만 전달하고 사진은 라벨 중계에 보내지 않습니다.

### 소분 기능 검증

```sh
npm run build
npm run test:dispensing
```

GS1 파싱, 유효성 검사, PC/휴대폰 권한 분리, 중복 요청, 만료, 두 브라우저 사이의 전송·출력 확인, 실제 바코드 디코더, 화면 크기를 검사합니다. 이 검증에서는 사진 분석과 Blob 저장만 테스트 대체물을 사용하며 실제 프린터를 출력하지 않습니다. 배포 후 실제 카운팅 API와 Blob 중계 동작도 확인해야 합니다.

## 화면과 촬영

- 일반 카메라, 실시간 카메라, 촬영 결과는 같은 1:1 정사각형 프레임을 사용합니다.
- 프레임을 채우는 중앙 영역을 잘라 사용하며 알약 모양을 가로·세로로 늘리지 않습니다.
- 미리보기의 표시 범위와 서버에 보내는 실시간·일반 촬영 이미지 범위가 같습니다.
- 원본 및 번호 포함 촬영 사진도 1:1입니다. 긴 변은 최대 2048px이며 작은 입력은 확대하지 않습니다.
- 갤러리 사진은 원래 비율을 유지합니다. 원본 JPEG/PNG/WebP 저장은 원래 파일을 사용합니다.
- 모바일 첫 화면에는 큰 카메라·갤러리 버튼을 표시합니다. 카메라 프레임은 화면 높이에 맞춰 줄어들고 촬영 버튼은 아래에 유지됩니다.
- 실시간 탭은 카메라를 자동으로 열며, 촬영·확인은 해당 시점의 이미지를 새로 분석합니다.
- 촬영·선택한 사진은 자동 분석합니다. 결과 화면의 `다시 촬영`으로 카메라를 열고, `다른 사진으로 세기`로 갤러리 사진을 선택합니다. 카메라나 사진 선택을 취소하면 기존 결과를 유지합니다.
- 사진 프레임에서 두 손가락으로 확대·축소하고 한 손가락으로 이동합니다. 사진만 확대되고 프레임과 번호 크기는 유지됩니다. 저장은 파일 다운로드를 사용합니다.
- 뒤로가기는 저장 창 → 촬영/실시간 화면 → 분석 중지 → 번호 수정 종료 → 확대 해제 → 사진 유지 확인 → 첫 화면 종료 확인 순서로 현재 상태에 맞춰 처리합니다.
- Android의 닫기 요청은 지원 브라우저에서 CloseWatcher로 처리하고, 브라우저 툴바 탐색에는 초기 진입부터 준비한 history 항목을 사용합니다. 사용자 조작에서도 이를 점검합니다. 페이지 이탈은 브라우저 기본 확인으로도 보호합니다. CloseWatcher가 없는 브라우저에서 처음 접속해 한 번도 터치하지 않은 경우, OS의 탭 강제 종료 등은 웹앱이 차단할 수 없습니다.
- 툴바 뒤로가기에서는 확인창/화면 처리를 즉시 실행하고 기존 history 항목을 복원합니다. 복원이 지연되거나 차단돼도 확인창 표시를 기다리지 않으며, 취소 등의 실제 사용자 터치에서 항목을 복구합니다. `popstate`에서 새 기록을 만들면 Chromium이 이를 건너뛸 수 있어 사용하지 않습니다. 결과 화면의 `뒤로` 버튼으로도 동일한 동작을 실행할 수 있습니다. 삼성 인터넷의 실제 OS 뒤로가기 동작은 기기 검증이 필요합니다.
- 사진은 서버 분석에 사용되며 서버에 저장하지 않습니다.

## 다른 PC에서 이어서 작업

```sh
git clone https://github.com/moschus1-alt/pharmacy-pill-counter-mvp.git
cd pharmacy-pill-counter-mvp
git checkout master
npm install
npm run build
```

정적 화면은 `dist/`, 브라우저 코드는 `src/`, 서버 진입점은 `api/analyze.py`입니다.
카메라의 공통 촬영 영역은 `src/camera-frame.js`, 모바일 레이아웃은 `style.css`에서 수정합니다.

서버 분석을 새 PC에서 실행·재배포하려면 별도로 보관한 `private-model/counter-model.tflite`가 필요합니다. 모델 가중치, 인증 설정, 환경변수는 GitHub에 포함하지 않습니다. UI 수정과 아래의 프레임 검증은 모델 없이 가능합니다.

## 검증

```sh
npx playwright install chromium
npm run build
npm run test:camera
```

검증은 임시 로컬 서버와 가상 카메라를 사용합니다. 5가지 화면 크기, 세로·가로 입력의 중앙 자르기, 원형 유지, 촬영 버튼 노출, 일반·실시간 프레임 일치, 저장 비율, 두 손가락 터치 확대와 이동, 화면별 뒤로가기, 반복 취소·새로고침·명시적 종료·카메라 권한 대기와 거부를 확인합니다. CloseWatcher 경로는 Chromium의 Escape 닫기 요청으로, 미지원 경로는 history 탐색으로 검사합니다. 분석 응답은 모의 처리하므로 실제 모델 정확도와 실제 휴대폰 OS 버튼 검증을 대신하지 않습니다.
`CHROME_PATH`로 설치된 Chromium 브라우저 경로를 지정할 수 있습니다. 결과 이미지는 `.test-results/`에 생성됩니다.

사진 속 실제 알약 수와 자동 분석 번호를 대조해 확인하세요.

## 의약품 바코드 자동 조회

출처: [건강보험심사평가원_약가마스터_의약품표준코드](https://www.data.go.kr/data/15067462/fileData.do), **2026-08-31 기준**, 공공누리 제1유형(출처표시). 원본 CSV 309,889행 중 검증번호가 유효한 309,888개 표준코드를 사용합니다. 원본/변환 파일 SHA-256, 다운로드 URL, 제외 행 수는 `data/drug-catalog-source.json`에 기록합니다.

- `GET /api/product-lookup?code=8806723002015`는 등록된 정확한 표준코드만 조회합니다. API 키나 개인/환자 정보 전송은 필요 없습니다. GS1에서 추출한 GTIN-14의 선행 0만 제거하며, 0이 아닌 포장 지시자는 보존합니다. 품목기준코드나 보험코드를 바코드처럼 취급하거나 인접 포장 코드를 추측하지 않습니다.
- 제품명, 업체명, 약품규격을 입력하고 제품총수량/포장형태는 참고 정보로 표시합니다. 제조번호·제품 사용기한은 스캔한 GS1 값에서만 가져오며 **소분 수량은 실제 촬영·확인으로만** 반영합니다. 원문 제품명을 임의로 잘라 넣지 않습니다. 라벨 제한(제품명 80자/규격 40자/업체 60자)을 넘으면 사용자가 포장과 대조해 편집해야 합니다.
- 데이터 기준일에 취소/양도종료된 코드, 동일 코드의 충돌 레코드는 자동 입력하지 않습니다. 종료일이 기준일보다 미래인 경우(예: `9999-12-31`) 종료된 것으로 취급하지 않습니다. 조회 중 새 스캔·직접 편집이 발생하면 이전 응답을 무시합니다. 오프라인/조회 실패에는 저장한 제품을 명시적으로 안내하고 수동 입력·재시도를 제공합니다.
- **정기 공개 파일의 스냅샷**이며 실시간 허가·급여 상태 확인 서비스가 아닙니다. 모든 유통 제품이나 신규 코드의 조회를 보장하지 않습니다. 새로운 공개 파일은 아래 절차로 갱신·검증·재배포합니다. 자동 갱신 일정은 설정하지 않았습니다.

```bash
# 공식 페이지의 최신 CSV를 다운로드하고 그 파일의 실제 기준일/URL을 지정
python scripts/import-drug-catalog.py /path/to/download.csv --as-of YYYY-MM-DD --download-url '공식 CSV 다운로드 URL'
npm run build
npm run test:products
npm run test:dispensing
```

임포트는 CP949 CSV를 검증해 재현 가능한 gzip 조회 파일을 생성합니다. 조회 함수만 `data/**`를 포함하며 브라우저와 Python 카운팅 함수에 전체 목록을 싣지 않습니다. 새 파일을 Git에 커밋하고 기존 비공개 카운팅 모델을 보존하는 배포 절차를 사용합니다.

실제 서비스 확인: `PILL_BASE_URL=https://pharmacy-pill-counter-mvp.vercel.app npm run test:products`. 제품 조회와 2D 파싱, 실제 포장별 결과, 이력 처리, 모바일 자동 입력을 검사합니다. 로컬 검증은 응답 지연·직접 편집·조회 장애·저장값 복구도 검사합니다. `checks/dispensing-production.mjs`는 실제 카운팅 및 PC 전송을 별도로 확인합니다(물리 프린터 출력 제외).


### GS1 판독과 PC 연결 표시

ZXing이 GS1 DataMatrix의 첫 FNC1을 ASCII 29로 반환하는 경우를 지원합니다. 선행 AIM 식별자/GS1 시작 문자만 정규화하고 제조번호·일련번호 사이의 GS 구분자는 보존합니다. `test:products`는 실제 FNC1 코드워드가 든 DataMatrix 이미지를 앱에 포함된 ZXing으로 판독해 조회까지 확인합니다.

소분 화면 상단에는 스크롤 중에도 보이는 PC 연결 카드가 있습니다. 미연결은 황색, 연결된 전송 PC의 이름과 PC 수신 대기 상태는 녹색, 수신 오류는 주황색으로 표시합니다. 카드를 누르면 연결 관리/QR을 열고, 카운팅 중에도 전송 대상 PC를 표시합니다. 연결은 출력 대상 등록 상태를 의미하며 물리 프린터의 온라인 상태를 검사하는 기능은 아닙니다. 만료된 등록과 서버가 종료를 확인한 연결은 해제 표시로 바뀝니다.


### 툴바 뒤로가기와 사용 종료

브라우저 툴바의 기록 탐색과 CloseWatcher 닫기 요청을 각각 검사합니다. `npm run test:navigation`은 첫 터치 전 툴바 탐색, 반복 취소, history.forward 지연/무응답, 새로고침, 이전 페이지 없는 탭에서 종료 후 다시 시작을 확인합니다. 기록 복원 중 빠르게 나가기를 누르면 현재 기록 위치를 확인한 뒤 종료합니다. 이전 페이지가 있으면 돌아가고, 없는 경우 정적 `exit.html` 사용 종료 화면으로 이동합니다. 오류 문구를 띄우거나 임의로 브라우저 탭을 닫지 않습니다.

브라우저의 의도적인 기록 건너뛰기/뒤로가기 방해 차단 정책, OS의 탭 종료는 웹페이지가 무효화할 수 없습니다. 자동 검증은 Chromium의 실제 history 탐색과 CloseWatcher(Escape) 및 지연/무응답 조건으로 수행하며 삼성 인터넷 실기기 검증을 대체하지 않습니다.


### QL-550 / DK-22210 출력

기본 용지는 DK-22210 29 mm 연속이며, 한 장 길이는 90 mm에서 조절할 수 있습니다. 다른 규격은 직접 폭·길이(12~200 mm, 0.1 mm 단위)를 입력합니다. 용지 설정은 기기에 저장하고 다음 소분에도 유지하며, 휴대폰에서 보낸 실제 크기를 PC 미리보기·인쇄 페이지에도 적용합니다. 테스트 라벨도 현재 선택한 크기를 사용합니다. 내용이 넘치면 전송/출력을 막고 연속 용지 길이를 늘리도록 안내합니다.

QL-550은 USB 프린터입니다. 윈도우 공유 설정만으로 휴대폰 인쇄 목록에 나타나는 구조가 아닙니다. 프린터를 설치한 PC에서 앱 → PC·프린터 연결 → 이 PC에서 라벨 받기를 누르고, 휴대폰에서 QR을 읽어 연결한 뒤 PC로 라벨을 전송하세요. PC에서 도착한 라벨을 열어 인쇄 대상으로 Brother QL-550을 선택합니다. 다른 PC의 공유 프린터를 이용하려면 먼저 출력 PC의 윈도우 프린터 목록에 추가해야 합니다.

PC 드라이버에서 29 mm 연속 용지와 앱의 한 장 길이를 맞추고, 배율 100%, 여백 없음, 머리글/바닥글 끔을 설정하세요. 사용자 정의 길이가 목록에 없으면 프린터 속성에서 등록합니다. 브라우저는 윈도우 프린터 목록이나 드라이버 용지 설정을 직접 바꾸지 못합니다. 자동 검증은 두 브라우저의 실제 전송/수신과 인쇄 페이지 크기를 확인하며 물리 QL-550의 급지·절단·바코드 판독은 실기기 확인이 필요합니다.


### 유팜데일리 자동 출력 연동 (0.8.4)

Python 유팜데일리의 기존 QL-550 출력 함수에 연결할 수신 모듈과 적용 지침을 `integrations/upharm-daily/`에 제공합니다. 배포된 `/integrations/upharm-daily.zip`에서 받을 수 있습니다. PC 연결 창에서 ‘유팜데일리 연결 파일 받기’로 임시 수신 권한을 내보냅니다. 이 저장소에는 실제 UPharmStats 코드가 없으므로 해당 PC에서 기존 출력 함수·설정 UI에 어댑터를 적용해야 동작합니다.

수신기 상태/프린터 이름을 휴대폰에 표시하며, 60초 이상 상태 갱신이 없으면 연결 끊김을 표시합니다. 서버의 생성 전용 처리권과 수신기의 영속 저널로 중복 인쇄를 막습니다. 응답 유실 후에는 결과 통보만 재시도하고, 접수 여부가 불확실한 라벨은 자동 재출력하지 않습니다. `spooled`는 드라이버 전달이며 실제 출력 완료가 아닙니다. `npm run test:upharm`은 실제 HTTP API와 Python 수신 모듈을 연결해 동시 처리권 요청, 응답 유실, 재시작, 프린터 오류 후 일시정지/재개를 검사합니다. 물리 프린터 콜백은 테스트 대역이며 Windows QL-550 출력은 PC에서 별도 검증합니다.
